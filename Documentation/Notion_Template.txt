## 📌 사용 목적

## 🎨 코드 블록 작성 가이드

### ✅ DO: 올바른 코드 블록

**1. 빈 줄로 논리적 구분**
```csharp
// 컨텍스트 주석

실제코드();  // 설명
```

**2. 최소한의 컨텍스트 제공**
```csharp
void OnDisable()
{
    SomeEvent -= Handler;  // ✅
}
```

**3. 여러 클래스는 분리**

**클래스 1**
```csharp
public class ClassA { ... }
```

**클래스 2**
```csharp
public class ClassB { ... }
```

---

### ❌ DON'T: 피해야 할 패턴

**1. 여러 줄을 빈 줄 없이**
```csharp
void Method() {
    Line1();
    Line2();
    Line3();
}
```
→ Notion에서 한 줄로 합쳐짐

**2. 여러 클래스를 한 블록에**
```csharp
public class A { ... }
public class B { ... }
public class C { ... }
```
→ 구분이 안 됨

**3. 컨텍스트 없는 단일 라인**
```csharp
SomeCode();
```
→ 이게 어디서 사용되는지 불명확

  - "메모리 누수" → 빨간색 볼드
  - "수정 완료" → 초록색 볼드
- [ ] 콜아웃 블록 추가 (프로젝트 소개, 핵심 요약)
- [ ] 토글 블록 사용 (긴 코드나 상세 설명)

## 💡 작성 팁

### 1. 간결함 유지
- 코드 블록은 **핵심만** (3-7줄 이내)
- 전체 구현은 파일 링크로 대체

### 2. 시각적 구분
- 섹션마다 구분선 사용
- 이모지로 섹션 구분 (📋, 🐛, 🎯, 💡, 🔧, 🗺️, 🛠️, 📈, 🎓, 🔗, 📝)

### 3. 일관성
- Before/After 패턴 일관되게 사용
- 체크 마크 일관성 (✅ ❌)
- 우선순위 이모지 (🔴 HIGH, 🟡 MEDIUM, 🟢 LOW)

### 4. 검색 가능성
- 파일 경로는 백틱(``)으로 감싸기
- 기술 용어는 **볼드**
- 태그 활용 (#bugfix #refactoring #unity)

## 🚀 자동화 워크플로우

1. **작업 완료** → Phase 구현 및 테스트 통과
2. **문서 생성** → unity-notion-documenter agent 실행
3. **Notion 임포트** → 생성된 .md 파일을 Notion에 import
4. **서식 조정** → Divider 교체, 색상 추가
5. **하위 페이지 연결** → 메인 페이지의 해당 Phase 섹션에 연결
